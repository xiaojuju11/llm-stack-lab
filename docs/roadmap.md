# 16 周排期与验收口径

按「每天 2 小时、每周 6 天」估算。实际快慢不重要，**里程碑的验收标准不能降**——降了就是自我欺骗。

## 里程碑

| 里程碑 | 时间点 | 判定标准（达不到就不往下走） |
|---|---|---|
| M1 能写出干净的后端代码 | 第 3 周 | 能独立写出带 pydantic 校验、异步调用、单元测试的 FastAPI 服务 |
| M2 能自己实现 Agent 循环 | 第 7 周 | 不看任何框架源码，手写出 think → act → observe 循环，含工具注册、最大轮次、错误回灌 |
| M3 能搭出可用的知识库问答 | 第 10 周 | 召回率与答案质量有量化数字（自建 30 条评测集），能说清每个环节为什么这么选 |
| M4 能交付一个完整服务 | 第 14 周 | 有鉴权、有日志、有健康检查、有 Dockerfile，能被别人按 README 一键跑起来 |

## 每周复盘三问

每周日花 20 分钟回答，写进当周专题 README 的复盘区：

1. **这周哪一段是我自己写出来的，哪一段是 AI 写完我照抄的？**（照抄的部分标出来，下周重写）
2. **哪个报错卡我最久，根因是什么？**（写下根因，不只是解法）
3. **如果现在让我给别人讲这个知识点，我卡在哪句话上？**（卡住的那句就是没懂的地方）

## 状态标记约定

专题 README 里的章节清单用三种状态：

- `- [ ]` 未开始
- `- [~]` 在写（不能停留超过 3 天）
- `- [x]` 已通过验收
