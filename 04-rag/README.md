# 04 - RAG：让模型回答它没被训练过的东西

RAG 的本质不是「向量数据库」，而是**检索质量决定答案质量**。这个专题的重点是：把「召回」这一步做出可度量的数字，而不是拼一个能跑的 demo。

## 目标

- 能针对不同文档类型选择切分策略，并说清为什么
- 能搭起「切分 → 向量化 → 存储 → 检索 → 重排 → 拼 prompt」的完整链路
- 能用混合召回（向量 + 关键词）解决专有名词召回不到的问题
- 能自建小规模评测集，量化召回率与答案质量，而不是凭感觉说「效果还行」
- 能识别 RAG 的失败模式：切分断裂、召回不全、上下文冲突、模型不忠于原文

## 验收标准

1. 对同一批文档用两种切分策略，用评测集跑出**两组不同的召回率数字**，并解释差异来源。
2. 构造一个「向量检索失败、关键词检索成功」的案例（用公司名/型号/代码标识符），并用混合召回修好它。
3. 评测集 ≥30 条，能给出「召回率 x%、答案可用率 y%」的结论，且知道错在哪几条。
4. 能说清：这套系统在什么情况下会答错，你怎么让它拒答。
