# 03 - Tool Calling：Agent 的最小能力单元

大模型只会生成文本。工具调用是让它「能干活」的唯一通道——**这一层没打通，后面的 Agent 都是空中楼阁**。本专题的核心产出是：关掉框架，手写一个完整的 think → act → observe 循环。

## 目标

- 说清 Function Calling 的本质：模型不执行任何东西，它只是输出一个「我想调用谁、参数是什么」的结构
- 能设计好用的工具 schema（描述怎么写、参数怎么约束、枚举该不该用）
- 能实现完整的调用闭环：模型要求调用 → 我执行 → 结果回灌 → 模型继续
- 能处理三种失败：模型给错参数、工具本身报错、模型死循环
- 能控制工具结果的 token 成本（结果裁剪、摘要）

## 验收标准

1. **不看任何框架文档，手写出 3.5 和 3.6 两个版本的循环。**
2. 能演示并解释「模型连续 3 次调用同一个工具同一参数」时，你的代码如何打断它。
3. 工具抛异常时，模型收到的是可读的错误描述而不是 HTTP 500——且能据此换一种做法继续。
4. 实战助手能完成一个需要 2 步以上工具协作的任务（例如「北京今天几度，比上海高多少」）。
