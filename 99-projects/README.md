# 99 - 成品区

学习仓证明你在学，**成品仓证明你能交付**。这里每个子目录都是一个能独立启动的服务，也是简历上要放链接的东西。

## 成品清单

| 目录 | 一句话说明 | 技术栈 | 状态 |
|---|---|---|---|
| `kb-qa/` | 私有文档知识库问答，带引用溯源 | FastAPI + RAG + SSE | 未开始 |
| `tool-agent/` | 能调多个工具的 Agent 服务，带流式与会话 | FastAPI + Tool Calling | 未开始 |
| `llm-gateway/` | 统一 LLM 网关：多上游、限流、重试、用量统计 | Go + net/http | 未开始 |

## 每个成品的准入门槛

达不到就不算成品，只算练习：

- [ ] 有 `README.md`：一句话定位、架构图、启动命令、接口说明
- [ ] 有 `.env.example`，密钥不硬编码
- [ ] 有 `/healthz`，能优雅关闭
- [ ] 有 Dockerfile，能 `docker run` 起来
- [ ] 有至少 5 个测试（单测 + 一个 httptest/TestClient 的端点测试）
- [ ] 错误返回是统一结构，不漏堆栈
- [ ] 有人能只读 README 就跑起来（找个同学试一次）

## 目录约定

```
99-projects/<name>/
├── README.md          # 定位 / 架构 / 启动 / 接口 / 已知限制
├── .env.example
├── Dockerfile
├── src/ 或 app/
└── tests/
```

## 写进简历的模板

> **xxx 项目**（个人项目 · 独立完成）
> 一句话：做什么、给谁用。
> 技术：FastAPI / LangGraph / Qdrant / Redis / Docker
> 难点一：<具体问题> → <怎么定位> → <怎么解决> → <效果数字>
> 难点二：……

**难点必须带数字**（召回率从 62% 提到 84%、P95 从 3.2s 降到 900ms）。没有数字的「负责了 xx 模块」在面试里撑不过追问。
